Core: Experimental optimistic start: activities and timers that lang marks `speculative` (because workflow code started them inside a speculative block) may start on this worker right away, before the server knows about them, when the namespace has the `optimistic_start` capability. Their outcomes reach the workflow within the same workflow task, and history gets ordinary activity and timer events. Lang reports block exits with `speculative_block_exited` and `speculative_block_active` on activation completions. Large batches go out as paginated workflow task completions when the namespace supports them. Once the server takes over a still running optimistic activity, it gets the same local timeouts as a polled one, and server cancellations reach it.
Core: Optimistic start metrics: `optimistic_activity_started`, `optimistic_activity_observed`, `optimistic_activity_handed_off`, `optimistic_activity_dropped`, `optimistic_timer_started`, `optimistic_timer_fired`, `optimistic_timer_cancelled`, `optimistic_timer_handed_off`, `optimistic_start_fallback` (with `fallback_reason`), `speculation_window_checkpoint` (with `checkpoint_reason`) and the `speculation_window_duration` histogram.
